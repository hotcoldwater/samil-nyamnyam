# 삼일냠냠 — AP 사내 간식 관리 웹앱 (D-1조)

탕비실 간식, 뭐가 남았고 줄은 어떤지 가기 전에 확인하는 웹앱입니다.
정명지님 디자인 시스템·프로토타입(v1)을 바탕으로, 빌드팀이 **실제로 데이터가 움직이는 앱(v2)** 으로 확장했습니다.

## 실행

- 배포: Vercel (정적 사이트, 빌드 명령 없음) — `index.html`이 저장소 맨 바깥에 있습니다.
- 로컬: 폴더에서 `python3 -m http.server` 후 `http://localhost:8000` 접속
- 로그인 없음. 데이터는 **이 기기 브라우저(localStorage)에만** 저장되는 데모 데이터입니다. 서버·DB·외부 API·API 키가 없어 300~400명이 동시에 접속해도 안전합니다.

## 심사위원 실행 가이드 (핵심 기능 재현 3단계)

1. **간식현황** — 시즌 간식 카드(남은 수량·별점·입고 시각)와 현재 대기 상태(최근 2분 제보 중앙값) 확인
2. **간식수령 및 제보** → 사원증 태그(모의) → 가져간 간식·내 뒤 줄 인원 선택 → **20P**. 완료 화면에서 남은 수량 변화(예: 12 → 10개)와 혼잡도 재계산 결과 확인
3. 완료 화면의 **리뷰 쓰고 30P 받기** → 간식 상세의 별점·리뷰에 즉시 반영
4. (확장) 내 계정 → **총무팀 화면(데모)**: 입고 예고 → 묶음 입고 → 구성원에게 알림 1건 / 부족 제보 → 바로 입고 처리 / 운영 분석

| 구분 | 주소(해시) | 내용 |

| 간식수령 | `#receive` → `#pick` → `#done` | 사원증 태그(모의) → 간식·수량 선택 → 줄 인원 → 완료(반영 결과, 2분 내 줄 인원 수정) |

| 메뉴 등록·입고 예고 | `#admin-menu` | 사진(일러스트 또는 촬영), 품목명 자동완성(기존 설정 불러오기), 시즌/상시, 알림 대상, 입고 예고 시간대 |

## 기획서 v5 규칙 구현

- 추정 수량 = 총무팀 확인값 − 구성원이 알려준 수령 수 (`약 n개`), 직전 입고량 30% 이하 **부족**, 0 **소진**
- 혼잡도 = 최근 2분 · 이용자별 최신 줄 제보의 **중앙값** Q, 3명 미만이면 **확인 중** / Q<5 여유, 5~14 보통, 15+ 혼잡 / 30초마다 재집계
- 수령 참여 1회 20P, 리뷰 1건 30P, 리뷰는 새벽 2시 기준 하루 단위
- 입고 1회에 알림 최대 1건, 알림 대상 품목이 있을 때만
- 동료 줄 제보·사원증 태그·포인트는 **모의 값**이며 화면에 '모의'로 표시
